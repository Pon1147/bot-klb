# Judge - Sufficient Context Validator

Validate tasks, requirements, and TODO lists against the Sufficient Context (SC) standard. Helps determine if requirements are clear enough to proceed with implementation.

## What This Skill Does

- **Judge user task files**: Evaluate .md files containing task descriptions
- **Judge Cline TODO lists**: Validate TODO items generated by Cline itself
- **Identify ambiguities**: Detect unclear terms, missing scope, undefined conditions
- **Generate clarifying questions**: Suggest questions to ask before proceeding
- **Provide SC verdict**: Clear PASS/FAIL with actionable feedback

---

## SC Standard Criteria

### Must Be Clearly Defined

| Criterion | What to Check | Example of Failure |
|-----------|---------------|-------------------|
| **Terms** | All technical/business terms defined | "Make it faster" - faster by how much? |
| **Scope** | What to do AND what NOT to do | "Calculate order total" - include VAT/shipping? |
| **Conditions** | When behavior triggers, inputs/outputs | "Send email" - when? to whom? with what data? |
| **Constraints** | Performance, security, legal requirements | "Optimize" - target response time? |
| **Consistency** | No internal contradictions | "Fast and comprehensive" without trade-offs |
| **Actionability** | Enough detail to start coding | "Build authentication" - which type? |

---

## Judging User Task Files

### Process

1. **Read the task file** using `read_file(path="task_file.md")`
2. **Analyze against SC criteria** (table above)
3. **Identify ambiguities** with specific line references
4. **Generate clarifying questions** (max 5, prioritized by impact)
5. **Provide verdict** with actionable feedback

### Output Format

```markdown
## Judge Result: [PASS/FAIL/NEEDS_CLARIFICATION]

### Ambiguities Found

| # | Type | Location | Issue | Impact |
|---|------|----------|-------|--------|
| 1 | Unclear scope | Line 5 | "Add payment feature" - which payment methods? | HIGH |
| 2 | Missing constraints | Line 12 | No performance targets specified | MEDIUM |

### Clarifying Questions

1. **HIGH**: Which payment methods should be supported? (Stripe, PayPal, local gateways?)
2. **MEDIUM**: What's the target response time for payment processing?
3. **LOW**: Should failed payments retry automatically?

### Recommendation

**Status**: Cannot proceed until HIGH priority questions are answered.

**Next Steps**:
- Ask user the clarifying questions above
- Update task file with answers
- Re-run judge to verify PASS
```

## Judging Cline TODO Lists

### When to Use

- Cline has generated a TODO list for a complex task
- User wants to validate TODOs before starting implementation
- TODO list comes from previous session/resume scenario

### Process

1. **Read TODO source** (file or conversation context)
2. **Evaluate each TODO item** against SC criteria
3. **Check dependencies** between TODOs
4. **Identify gaps** - missing TODOs for edge cases
5. **Generate improvements** for unclear items

### Output Format

```markdown
## TODO List Judge Result: [PASS/FAIL/NEEDS_IMPROVEMENT]

### Item-by-Item Analysis

| # | TODO Item | Status | Issues |
|---|-----------|--------|--------|
| 1 | "Set up database" | ⚠️ UNCLEAR | Which DB? Schema? Migrations? |
| 2 | "Create user model" | ✅ CLEAR | Well-defined |
| 3 | "Add authentication" | ❌ TOO_VAGUE | JWT? OAuth? Session? |

### Missing TODOs

Based on the task scope, consider adding:
- [ ] Define error handling strategy
- [ ] Add rate limiting for auth endpoints
- [ ] Create migration scripts

### Improved TODO List

```markdown
- [x] Set up PostgreSQL database with schema v1
- [x] Create User model with email, password_hash, created_at
- [ ] Implement JWT authentication with 24h expiry
- [ ] Add rate limiting (100 req/hour for login endpoint)
- [ ] Create database migration scripts
```

### Recommendation

**Status**: TODO list needs refinement before implementation.

**Action**: Replace vague items with improved version above.
```

## Ambiguity Detection Patterns

### Type: Undefined Terms

**Look for:**
- Vague adjectives: "fast", "efficient", "user-friendly"
- Unspecified technologies: "database", "cache", "queue"
- Generic actions: "optimize", "improve", "fix"

**Questions to ask:**
- "What does 'fast' mean in measurable terms? (e.g., <200ms response)"
- "Which specific technology? (PostgreSQL, MongoDB, Redis?)"
- "What's the current issue and target improvement?"

---

### Type: Unclear Scope

**Look for:**
- No boundaries defined
- Missing exclusions
- "And so on" / "etc."
- Open-ended requirements

**Questions to ask:**
- "What's explicitly OUT of scope?"
- "Which variants/cases should NOT be handled?"
- "What's the minimum viable version?"

---

### Type: Missing Conditions

**Look for:**
- No trigger conditions
- Undefined inputs/outputs
- Edge cases not addressed
- Error handling not specified

**Questions to ask:**
- "When exactly should this execute?"
- "What are the expected input formats and ranges?"
- "How should errors be handled/reported?"

---

### Type: Missing Constraints

**Look for:**
- No performance targets
- Security requirements absent
- Compliance needs not mentioned
- Resource limits undefined

**Questions to ask:**
- "What's the target latency/throughput?"
- "Any security/compliance requirements? (GDPR, SOC2, etc.)"
- "Resource constraints? (memory, CPU, storage)"

---

## Verdict Scale

| Verdict | Meaning | Action |
|---------|---------|--------|
| **PASS** | All criteria met, ready to implement | Proceed with implementation |
| **NEEDS_CLARIFICATION** | 1-2 low-priority ambiguities | Ask quick questions, then proceed |
| **FAIL** | High-priority ambiguities blocking implementation | Must clarify before any coding |

---

## Quick Judge Checklist

For rapid evaluation, check these:

```
- [ ] Can I start coding RIGHT NOW with this info?
- [ ] Would two developers implement the same solution?
- [ ] Are acceptance testable criteria defined?
- [ ] Are edge cases and error handling considered?
- [ ] Is the scope bounded (what's NOT included)?
```

**If any NO → Verdict: FAIL**

## Example: Judge a Task File

### Input Task File

```markdown
# Task: Add User Dashboard

Create a dashboard for users to see their data.

Requirements:
- Show user statistics
- Display recent activity
- Make it look good
- Add filtering options
```

### Judge Output

```markdown
## Judge Result: FAIL

### Ambiguities Found

| # | Type | Location | Issue | Impact |
|---|------|----------|-------|--------|
| 1 | Unclear scope | "user statistics" | Which metrics? (orders, views, revenue?) | HIGH |
| 2 | Undefined terms | "recent activity" | What defines "recent"? (24h, 7d, 30d?) | HIGH |
| 3 | Undefined terms | "look good" | No design specs or references | MEDIUM |
| 4 | Unclear scope | "filtering options" | Filter by what? Date, type, status? | HIGH |

### Clarifying Questions

1. **HIGH**: What specific statistics should the dashboard show?
2. **HIGH**: What's the time range for "recent activity"?
3. **HIGH**: What filtering options are needed? (date range, activity type, etc.)
4. **MEDIUM**: Any design system or reference for "look good"?

### Recommendation

**Status**: Cannot proceed. Missing core requirements.

**Next Steps**: Ask questions 1-3 before any design/implementation work.
```

## Integration with Workflow

### When to Trigger This Skill

1. User explicitly asks: "Judge this task", "Is this clear enough?", "Validate requirements"
2. Before starting large implementations (auto-trigger consideration)
3. When resuming from previous session with TODO list
4. When user creates a new task/brief file

### After Judging

- If **PASS**: Proceed to implementation phase
- If **NEEDS_CLARIFICATION**: Ask questions, wait for answers, re-judge
- If **FAIL**: List blocking issues, ask HIGH priority questions first

## Per-Judge Checklist

```
- [ ] Read full task/TODO source
- [ ] Check all 6 SC criteria (Terms, Scope, Conditions, Constraints, Consistency, Actionability)
- [ ] Identify ambiguities with line references
- [ ] Prioritize questions (HIGH/MEDIUM/LOW)
- [ ] Limit questions to max 5 most impactful
- [ ] Provide clear verdict (PASS/FAIL/NEEDS_CLARIFICATION)
- [ ] Give actionable next steps
